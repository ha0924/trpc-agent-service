# 一期建表范围与初始数据

一期建表 12 张，覆盖四条链路：识别租户、定位会话、装配 Runtime、数据落库。

**建表 DDL 见 [`../数据模型设计.md`](../数据模型设计.md) 第 5 节**，本文不重复，只说明一期建哪些、为什么推迟其余的、以及预置什么数据。

## 1. 建表范围

| 表 | 一期作用 |
|---|---|
| `tenants` | 租户上下文的来源 |
| `agent_apps` | 定位 Agent |
| `agent_versions` | Runtime 装配的输入，含 Prompt 与模型配置 |
| `agent_tool_bindings` | 本版本可用哪些 Tool |
| `agent_extension_bindings` | 本版本启用哪些 Plugin、Guardrail、Callback |
| `agent_mcp_bindings` | 本版本使用哪些 MCP 服务 |
| `agent_skill_bindings` | 本版本挂载哪些 Skill |
| `agent_deployments` | 决定用哪个版本，版本固化的依据 |
| `channel_bindings` | 从入站消息定位租户与 Agent |
| `sessions` | 会话定位与版本固化 |
| `session_events` | 会话事件，需验证 `sequence` 正确 |
| `inbound_events` | 入站幂等，ACK 前落库 |

## 2. 推迟到二期

| 表 | 推迟原因 |
|---|---|
| `tool_definitions` | 一期绑定表直接存 Tool 名，实现在代码中注册。定义表用于 Admin 页面渲染与反查影响面，二期需要 |
| `extension_definitions` | 同上 |
| `mcp_servers` | 一期不实际连接 MCP，绑定表可为空 |
| `knowledge_bases` 与绑定表 | 一期无知识库 |
| `channel_users` | 一期为 Mock 通道，`external_user_id` 可直接作为内部用户。映射规则在接入真实通道且存在第二个租户后才有意义 |
| `backend_configs` | 一期只有一个后端 |
| `backend_bindings` | 同上 |

推迟后端两张表不影响 Storage Router 的成立。路由的关键是接口形状与查找逻辑，而非配置来源：`StorageRouter` 按 `tenant + agent + data_type` 三元组查找的签名与内部逻辑在一期即定死，映射先从配置文件读取。二期改为读表时只动 Provider 内部，接口不变。同时省去解析连接引用与建立连接池的一整套逻辑。

`agent_mcp_bindings` 与 `agent_skill_bindings` 一期建表但不写入数据。建表的目的是装配逻辑按四类能力统一遍历，二期接入时不改装配结构。

## 3. 初始数据

预置以下数据，构成一条可运行的链路：

```text
tenants                   tenant-demo
agent_apps                tenant-demo / assistant
agent_versions            tenant-demo / assistant / v1，status=published
agent_tool_bindings       v1 → search、calculator，均为 allow
agent_extension_bindings  v1 → callback / request_logger
agent_deployments         tenant-demo / assistant / prod，routes=[{v1,100}]
channel_bindings          cb-demo，channel=mock，webhook_path=/webhook/mock/demo
```

`agent_mcp_bindings` 与 `agent_skill_bindings` 不写入数据。

`sessions`、`session_events`、`inbound_events` 由运行时写入，不预置。

## 4. 装配读取顺序

装配 Runtime 需读取版本配置与四张绑定表，键完全一致，可合并为一次查询后在内存分组：

```text
按 tenant + agent_app + version 读 agent_versions   得到 Prompt 与模型配置
按同一组键读 agent_tool_bindings                    得到 Tool 列表与 allow / deny / ask
按同一组键读 agent_extension_bindings               按 kind 分组并依 priority 排序
按同一组键读 agent_mcp_bindings                     一期为空
按同一组键读 agent_skill_bindings                   一期为空
```

装配结果按 `tenant + version` 缓存。已发布版本不可变，缓存不会失效，因此上述读取只发生在首次装配。

扩展列表需按列表遍历挂载，不可写死。一期该列表只有一个日志类 Callback，二期往列表中追加即可，装配签名不变。
